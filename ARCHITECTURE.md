# Архитектура Ch00chKA

Проект устроен как модульный монолит. Telegram, AI, SQLite и медиазагрузчики
подключаются через явные границы, но разворачиваются одним приложением.

## Обработка сообщения

1. Telegram adapter преобразует `Message` в `NormalizedMessage`. Базовые
   обращения состоят из фактических имени и username бота. Администратор каждого
   чата может задать исходные обращения через `/generate_aliases`; AI создаёт
   производные, которые сохраняются в SQLite и проверяются до participation agent.
   Для ответа на сообщение также сохраняется snapshot автора и текста `reply_to`,
   а выбранная Telegram-цитата передаётся отдельно. Эти данные видят Participation,
   Research, Actor и Observer, поэтому местоимения и короткие ответы разрешаются
   относительно конкретной реплики и процитированного фрагмента.
2. `UrlActionPlanner` создаёт независимые media actions без знания о загрузчиках.
3. `MessageProcessor` получает `ActionPlan` и запускает AI-контур отдельно.
4. Participation agent решает, нужен ли текстовый ответ, и среди ограниченного
   списка недавних участников отмечает людей, которые нужны для понимания
   обращения, reply, цитаты или упоминания.
5. Research agent независимо решает, нужны ли свежие внешние сведения, и
   формирует не более двух запросов. Код разрешает только фиксированные источники:
   Wikipedia для общих сущностей, Apple iTunes Search для музыки и внутренний
   SearXNG для широкого поиска по открытым веб-источникам. Аккаунты и API-ключи
   для них не нужны; произвольные URL модель открывать не может.
6. Долговременная память разделена на два слоя: `chat_state` — краткое общее
   состояние чата, и отдельные профили участников по `(chat_id, user_id)`. При
   вытеснении старых сообщений один memory-вызов обновляет оба слоя, не смешивая
   сведения о людях с общим состоянием. `MemoryRouter` выбирает максимум несколько
   профилей: автора, адресата reply, распознанных упомянутых людей. Поэтому актёр
   не получает каталог всех участников.
7. Context Builder собирает personality, chat_state, выбранные профили, недавние
   сообщения и, если исследование понадобилось, ограниченный факт-пак. Внешний
   текст и память чата помечаются как недоверенные данные и не могут задавать
   инструкции агентам.
8. Actor создаёт черновик ответа.
9. Observer принимает либо отклоняет ответ, а также сверяет явные актуальные
   утверждения с факт-паком. Первое содержательное отклонение (`revise` или
   `block`) отображается в чате как `Filtered`. Повторная генерация сохраняется
   только для технически оборванного по лимиту ответа.
   `finish_reason` сохраняется вместе с черновиком: ответ, остановленный по
   лимиту, всегда перегенерируется короче, а другие незавершённые ответы
   блокируются и не попадают в чат.
10. Принятый ответ сохраняется и отправляется в Telegram.
11. `YtDlpMediaAdapter` исполняет media actions отдельно от AI-контура. Он
   принимает только allowlist доменов YouTube, TikTok и Instagram, скачивает
   публичное видео через `yt-dlp`, приводит контейнер к MP4 через `ffmpeg` и
   удаляет временные файлы после отправки. Одиночные изображения уходят как
   Telegram photos, а последовательности фото и видео — альбомами до десяти
   элементов. Если `yt-dlp` не умеет раскрыть изображения Instagram-карусели
   или TikTok Photo Mode, `gallery-dl` скачивает до `MEDIA_MAX_ITEMS` фото;
   при необходимости они уходят несколькими альбомами. Видео по-прежнему
   остаётся на пути `yt-dlp` + `ffmpeg`. Опциональная функция
   `delete_source_links` удаляет исходное сообщение только после успешной
   отправки всех распознанных медиа из него.

Observer не изменяет personality и не создаёт циклов саморедактирования.
Версия системного контракта хранится в `ch00chka/ai/prompts.py`.

## Каталоги

- `ch00chka/domain` — модели без внешних зависимостей.
- `ch00chka/application` — orchestration и интерфейсы компонентов.
- `ch00chka/ai` — Participation, Actor, Observer, prompts и LLM gateway.
- `ch00chka/infrastructure` — SQLite repository.
- `ch00chka/presentation` — Telegram adapter.
- `ch00chka/integrations` — загрузчики медиа и другие внешние адаптеры.

## Тестирование агентов

Без Telegram:

```powershell
python -m scripts.agent_smoke_test "Стоит ли боту отвечать на это сообщение?"
python -m scripts.agent_smoke_test "Привет, бот" --force-reply
```

Автоматические тесты orchestration:

```powershell
python -m unittest discover -s tests -v
```

Модели и endpoint меняются переменными `AI_MODEL`,
`AI_PARTICIPATION_MODEL`, `AI_RESEARCH_MODEL`, `AI_OBSERVER_MODEL` и
`AI_BASE_URL`.
Thinking mode управляется явно через `AI_THINKING_ENABLED`; по умолчанию он выключен.
Исследование отключается через `AI_RESEARCH_ENABLED=false`. Время ожидания,
срок кеша и размер факт-пака задаются `RESEARCH_TIMEOUT_SECONDS`,
`RESEARCH_CACHE_TTL_SECONDS` и `RESEARCH_MAX_FACTS`. Для полноценного общего
web-поиска достаточно добавить новый адаптер за интерфейсом `ResearchBackend`,
не меняя Participation, Actor или Observer.

SearXNG работает отдельным внутренним сервисом Compose без опубликованного порта.
JSON API включён только для общения с ботом; адрес задаётся контейнеру через
`RESEARCH_WEB_BASE_URL`. Секрет экземпляра хранится в `.env` как
`SEARXNG_SECRET`.
Образ зафиксирован по digest проверенной версии `2026.8.17-374939b88`, поэтому
обновление поискового сервиса выполняется осознанной заменой digest.
Алиасы конкретного чата настраиваются командами `/generate_aliases` и
`/get_aliases`; менять их может только администратор.
При старте накопившиеся Telegram updates удаляются, чтобы после простоя бот не
отвечал на старую переписку. Это отключается через
`TELEGRAM_DROP_PENDING_UPDATES=false`.

Медиа по умолчанию ограничено 10 минутами и 48 МБ. Параметры меняются через
`MEDIA_MAX_DURATION_SECONDS`, `MEDIA_MAX_BYTES` и `MEDIA_TEMP_DIR`. Cookies и
аккаунты для первой версии не используются. Число одновременно работающих
загрузчиков задаётся через `MEDIA_MAX_CONCURRENT_DOWNLOADS` (по умолчанию 2).

## Локальный Telegram Bot API

Режим выбирается одной переменной `TELEGRAM_API_MODE`. Значение `cloud` использует
обычный облачный Bot API и лимит медиа 48 МБ; пустые `TELEGRAM_API_ID` и
`TELEGRAM_API_HASH` при этом допустимы. Значение `local` активирует профиль
локального сервера в режиме `--local`, переключает aiogram на его внутренний URL,
увеличивает таймаут отправки и поднимает лимиты загрузчика до 1,9 ГБ и четырёх
часов. `COMPOSE_PROFILES=${TELEGRAM_API_MODE}` уже задан в `.env`, поэтому второй
Compose-файл не нужен. Порт сервера наружу не публикуется, его состояние хранится
в отдельном volume.
Docker-образ Bot API зафиксирован по проверенному digest и не обновится
неожиданно при следующем деплое.

Для запуска нужны `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` с `my.telegram.org`.
Перед первым переходом бот должен быть явно выведен из облачного Bot API:

```bash
docker compose run --rm --no-deps bot python -m scripts.telegram_api_migrate --yes
# Затем поменять TELEGRAM_API_MODE=cloud на TELEGRAM_API_MODE=local в .env
docker compose up -d --build
```

`logOut` не выполняется автоматически, потому что он меняет маршрутизацию бота и
на десять минут блокирует обратный вход в облачный Bot API.

Для TikTok extractor автоматически использует browser impersonation из
`curl_cffi`. Его версия должна
оставаться совместимой с `yt-dlp`; она зафиксирована в `requirements.txt`, потому
что несовместимая более новая версия незаметно отключает challenge solver.
Сам `yt-dlp` закреплён на версии 19 августа 2026 года: в ней исправлен TikTok
challenge, который ещё воспроизводился в сборке от 4 августа.
TikTok может дополнительно блокировать IP дата-центров. Для такого случая без
изменения кода предусмотрены `MEDIA_PROXY_URL` и cookies в Netscape-формате,
понятном `yt-dlp`. Compose монтирует отдельные read-only файлы из
`./cookies/` для YouTube, TikTok и Instagram; пути задаются переменными
`MEDIA_YOUTUBE_COOKIES_FILE`, `MEDIA_TIKTOK_COOKIES_FILE` и
`MEDIA_INSTAGRAM_COOKIES_FILE`. Старый `MEDIA_COOKIES_FILE` остаётся запасным
общим файлом для платформы, у которой не задан отдельный путь. Перед скачиванием
бот создаёт постоянный, доступный для записи jar для каждой платформы в
`MEDIA_COOKIE_JAR_DIR` (в Compose — `/data/cookies` внутри named volume). Именно
этот jar получает `yt-dlp`, поэтому обновления cookies переживают рестарт.
Исходный экспорт остаётся неизменяемым. После замены экспортированного файла
нужно один раз запустить контейнер с `MEDIA_COOKIE_JAR_RESET=true`, затем вернуть
значение в `false`. Cookies и прокси не выводятся конфигурацией приложения.
